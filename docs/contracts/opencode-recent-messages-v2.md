The actual `session.message.list` operation is `GET /api/session/{sessionID}/message`. Its `order` query accepts `asc` or `desc`, with nullable string `limit` and opaque `cursor`. Its optional `type` is a single message-type enum, not a combined user/assistant filter. The result contains `data` and `cursor.previous`/`cursor.next`. Assistant `time.completed` is optional; `finish` accepts stop, length, tool-calls, content-filter, error and unknown. User records expose no parent ID. A local SDK's different version is not used as proof of this contract.

`opencodeClient.getRecentMessages(sessionId, limit = 32, directory?)` requests one descending page and returns mapped records in chronological order. It rejects noninteger/out-of-range limits before transport and rejects an overfilled raw page. It does not follow cursors, truncate an oversized page or reinterpret the first ascending page as recent history. The bound counts raw records, including nonconversation events; it does not promise 32 complete turns. Existing `getMessages` and `getMessagesPage` retain ascending initial order and unchanged opaque-cursor behavior.

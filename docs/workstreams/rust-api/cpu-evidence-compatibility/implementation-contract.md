# Bounded pure projection and converter splice

The owned capture-projection.mjs validates decoded data and returns only configuration/provenance/measurement projections. It reads no files, performs no workload or DB/process action and returns no approval, principal, brand or runtime authority. Thirteen pure-data tests use explicitly synthetic decoded records; they never call generateApproval or emit a review/approval file.

Supported producer decoders are closed and source-hash pinned: model-r1 (the unchanged11-key model binding), resource-probe-r1 (the10-key probe without retained host numeric measurements) and resource-probe-r2 (the10-key producer with original producer/child source hashes and two retained measurements). Kernel owner executable/source and the child sources are pinned to the audited public versions. The exact original command/input facts, raw grant/receipt hashes, bindings, owner, source-specific hard limits/readback, boot/namespace, peaks and positive joins must agree. R2 additionally requires the producer source file itself in both hashed readonly inputs and retained inputFacts, exact producer schema and original operator/child timestamps/reserve/availability. Neither host sample enters the stable configuration digest. Missing r1 measurements remain null, never copied or inferred. Legacy decoders require Root's explicit source attestation in the new protected review; the old grant is not retroactively claimed to contain a producer field.

Root supplies a new root-cpu-qualification-review-v2 through the same protected review reader. Its bindings are the closed root-cpu-configuration-v1 projection; owner is separate, and kernelEnvironment contains exact bootId/namespaceInode. captureDecoders is keyed by expected case. Each supported descriptor has exactly decoder, producerSha256, grantPath, grantSha256, receiptSha256 and legacySourceAttested. These are Root's review claims, not authority inferred by the pure helper; the converter must first read the actual protected review/capture/grant and hash the original bytes.

The exact splice changes only the converter's schema/binding decoding and digest linkage, adds the pure module, and uses the existing bounded strict duplicate-key-refusing JSON parser for review/capture/grant/closure and JSON event lines. preimages pin the converter to148251806cf9333209822b17ddd93941b5f17d84d4c65622fa1fb9d62550a86f and record the parser source hash. Raw captures and their field names/bytes remain unchanged. The raw installedClosureSha256 must equal the actual protected closure-file SHA and reviewed dependencyClosureSha256; sealed RECORD/environment/VAD and exact protected profile/assets checks remain in the original converter. No arbitrary alias fallback or unknown key dropping exists.

Helper, witness and production-wire producers deliberately have NO decoder. assertCaptureDecoder rejects them before reading their case files. The converter still calls all five cases, then requires its existing genuine actual Core wire receipt, full payload envelope, original helper/witness joins, retired control/leaves, no fixture evidence, Root approval, positive components and exclusive protected output. Those gates were not removed. Consequently this bounded proposal cannot generate a complete approval today. Real source/interfaces and their reviewed provenance must exist before adding those decoders; a generic helper with a matching configuration is insufficient. The existing strict separate Core wire binding check is intentionally retained pending its actual supported producer contract.

qualificationDigest retains original review/closure/Core wire/capture/stdout/stderr hashes and adds each raw grant hash, decoder/schema and stable projection hash. The actual measured peak arithmetic, mandatory positive values, no-OOM/limit-hit checks and bounded lifetime/custody/no-overwrite behavior remain unchanged. The proposal does not convert sampled leader RSS into a hard aggregate RAM guarantee.

Generate the minimal two-target patch/preimages using prepare-converter-splice.mjs with the explicit existing read-only integration root, and run git apply --check there. Canonical writes belong to Root. The new pure module's canonical target is docs/workstreams/voice/cpu-qualification/capture-projection.mjs. Existing API parser code is reused, not modified. Tests run using existing Node with TEMP/TMP/TMPDIR in the SAME authorized coordination/rust-api root and NODE_DISABLE_COMPILE_CACHE=1. No build/dependency/private-evidence/model/runtime/approval execution occurs.

Only the minimal source/test/generator/patch/preimages/contracts under this owned docs prefix and a small final TAP/single updated receipt/status in the same C-backed output root are retained for Root integration. No disk fixtures, caches, dependencies, compiler or approval outputs were generated. Prior rejected cleanup paths remain untouched. Remaining actual five-case, Core wire, helper/witness and Root review/approval acceptance stays open.

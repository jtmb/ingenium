# Linux CPU resource admission source proposal

This bounded worker proposal stays under this docs prefix. Root alone applies the six canonical targets in `linux-cpu-admission.patch`. `preimages.json` pins both manager files to the exact `5c41af5e` bytes; the current integration composition also passes `git apply --check`. The patch preserves the existing payload gating, context release, Core128 cascade and original control ownership. It adds no database, journal, credit writer, UI grant or renderer-supplied resource policy.

`createLinuxCpuSupervisor` privately assembles the actual `ManagedCpuProfile` and `ManagedCpuSupervisor`. The product factory exposes no injected capacity, spawn, fetch or positive-retirement port. Fixed server-owned paths and actual Core `bindContext`/`currentScope` are mandatory. Root still owns installation into its authenticated request path; this source proposal does not qualify that integration.

The concrete Linux probe reads the original unified cgroup v2 membership, cgroup namespace, boot, mount identity and every visible ancestor up to the fixed `/sys/fs/cgroup` mount. Memory and task limits must include finite bounds; headroom uses actual current usage and host MemAvailable. CPU uses effective cpuset and applicable quota ceilings. Missing, malformed, all-unbounded memory/tasks, identity replacement and unknown facts refuse admission. These read-only snapshots are not an exclusive kernel reservation or a guarantee against competing workloads, hidden ancestors, subsequent pressure, OOM or throttling. The actual deployment must qualify its visible hierarchy and finite Kubernetes limits.

The protected static approval file is private mode0600 under an owned private directory; ancestors and code/model paths reject symlinks and writable custody. `resource-approval.mjs` defines the exact version1 schema, also represented in `CpuResourcePlan`. It binds the loaded profile digest, interpreter and complete worker bundle, helper/witness source, exact model manifest/assets, thread count, worker address-space cap, stage components, qualification evidence digest, expiration and bounded model/witness lifetimes. Model and interpreter hashes are streamed before the helper fork. File size validates identity and bounds reads; it is never converted into a memory estimate. Original file identities are checked again before effects. The worker address-space cap is not aggregate model/helper/witness RSS.

No production approval, measured peak or illustrative production number is supplied. `qualificationDigest` references external operator-approved qualification evidence; a correctly shaped digest does not prove that measurements happened. The static protected file is an approval authority and must be installed only after Root obtains genuine measurements for the exact interpreter/code/model set, threads, cgroup layout and workload envelope. Required measurements cover cold resident models plus warmup/helper/witness/probe overhead; hot additional workspace plus witness/probe overhead; witness-only memory/tasks/CPU; and relevant process/thread peaks. Hashing/preflight, concurrency, bounded deadlines and limit interaction belong to that qualification. Expiry permits at most60seconds of separately bounded retirement-witness grace and never an expired hot grant.

Admissions are process-private WeakMap originals bound to the manager's actual scope/owner, profile and cgroup identities. Every effect checks the currently owned manager scope and fresh Core selected-original-scope authority. Started controls additionally re-read the exact running original Core control. Hot reuse has its own manager recheck and uses incremental headroom rather than charging resident models twice. A process-wide occupied slot prevents parallel model scopes; original Core controls retain cold-restart ownership.

The manager patch makes `admitCpuWitness` and `releaseCpuWitness` required callbacks at the actual recovery-witness fork site. Witness cleanup needs the exact original control/profile but no new UI grant. Witness-only accounting can precede cold model admission. There is at most one witness allocation, with its own opaque token and deadline. A completed witness allocation can release its incremental slot only after the actual original exit, close, stdout, stderr and input joins. This does not establish model-tree retirement: the existing manager proof validation and Core physical retirement still govern that separate decision. An attempted fork that throws, a timeout or a missing mount never synthesizes retirement.

`inspectResourceRetirement` reads the manager's private proof registry. Only its positively retired original group or its internally sealed before-fork proof can release a base allocation. It also distinguishes actual witness joins from a source-sealed witness path before any launch call. Caller booleans, JSON copies, PID/health/timeout observations and per-operation proofs cannot release. Retirement matches the exact previously bound scope object even when recovery has replaced its current map entry; this historical private proof provenance is deliberately distinct from the current-map requirement for new effects. Approval expiration or UI revocation never frees an allocation. An unresolved fork/join/release remains conservatively occupied.

Root private-retirement integration requirement: retain the context bound to an actual original scope while that scope is current. For physical cleanup of that historical original, select the exact scope from the actual private proof accessor and match the retained context, original scope/owner/control/profile; do not fabricate a fresh UI grant or require the old scope to remain map-current. The minimal manager patch selects its private proof's scope for `requireOriginalResource` only when action is `retireOriginal`, retaining all existing owner/operation/control and proof-kind checks; every other action still selects the current map entry. Existing `verifyRetirement` already uses its private proof registry with original tuple checks. The resource accessor is group/witness-specific: it does not promote CPU or per-operation sealed-no-start proofs to a base-resource retirement proof. Any separate per-operation private callback must keep the manager's existing exact proof validation and must not use resource release as substitute authority. Root owns the actual request-context changes and their integration tests.

Validation uses13 Node VM tests with actual proposed manager code and actual profile custody, tiny inert protected files, synthetic kernel facts and a stream-only child fixture. No OS model/witness process, model execution, device, real kernel write or inference occurs. Synthetic tiny budgets prove policy behavior only. The in-memory strict consumer/declaration check uses the actual Core contracts and proposed manager types, with no compiler output. Neither check establishes Windows qualification, Linux runtime acceptance, live capacity, actual resource peaks or the full Veyra goal.

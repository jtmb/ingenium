# Hosted voice ledger draft v1

SQL128 is reserved by Root. All proposals stay in this directory. The durable table belongs to the existing Core connection and transaction owner; there is no separate database, journal, transport, model execution or Native Rust operation authority.

`createCoreVoiceOperationLedger(ports)` provides synchronous `reserve(context, original, owner)`, `read(context, operationId)`, `cas(context, change)`, `settle(context, change)`, and `quarantine(context, operationId, expectedRevision, reason)`, plus the private CPU/control methods in `contract-v1.ts`. Reads return metadata or null. Mutations return metadata and use the existing immediate Core transaction/checkpoint. Reservation returns `{accepted, fresh, operation}`; an existing original always has `accepted:false, fresh:false` and cannot authorize dispatch again. A unique exact-scope/requestId constraint prevents a new UUID or kind from bypassing this rule.

The voice scope is exactly the nine keys in `packages/veyra-voice/session.mjs`, including the string `executionRevision`. CPU identity is separately the exact nine fields in the existing CPUv2 contract: its `generation` is a UUID, not the integer voice `turnGeneration`. CPU `requestId === operationId` is distinct from the voice service's readable requestId. CPU bootId identifies Python; original owner bootId identifies the Node supervisor and must not be equated. The server-owned original UUID, CPU identity, non-secret lease reference, input SHA256 and scope are immutable. No transcript, PCM/WAV, text, bearer credential or private headers enter this table. The control recovery endpoint identity is a non-secret owner reference, never a renderer URL or transport authority.

Required synchronous `currentScope(context, requested, action)` must revalidate actual API identity/CSRF/permissions and the actual selected account/conversation/agent/execution binding. It returns that verified scope, actual browser auth-session ID, explicit authorized workspace ID, user/workspace/runtime epochs, context deadline, and original private process owner lease. No fallback exists. Core independently checks actual users/auth_sessions, active organization/membership/project, project editor or organization owner/admin for execution, authorized workspace and ready runtime isolation/epochs/lease/absolute deadline. Null project/org scopes remain valid portable shapes but are refused by this hosted-only owner: no global/default/native mapping is invented.

Public reserved→running uses checked CAS. Quarantine settles public `terminal/unknown` irreversibly without claiming retirement. Positive public settlement requires `verifyRetirement(context, operation, proof)` from the actual closed owner, matching original CPU identity when present, Node owner/boot/generation/lease, retained UUID, drained=true, outcome and exact optional result digest. A boolean/caller-shaped proof is insufficient. A CPU terminal ACK never settles public completed; its response fingerprint must be retained separately, then the actual consumer settles. Terminal public fields cannot change even when private resource metadata is completed later. Deadlines, missing records, new boots, health/PID absence and cancellation ACKs cannot prove retirement.

Private `requireOriginalResource(context, operation, action, request)` validates the held original Node capability and opaque physical proof. It must return its own operation/owner/instance facts, never echo renderer metadata. This callback gates private read/list/control binding, retain/fingerprint/quarantine and retirement after UI selection changes; it cannot authorize a new dispatch. Actual joins/helper pidfd/ECHILD/EOF verification happens in the original owner before a synchronous proof-token check inside Core. No asynchronous I/O occurs in the SQL transaction. Missing callbacks reject construction.

Only ACKed `retainCpu` advances CPU revision. Bound→reserved, reserved→reserved, reserved→running, uncertain and terminal retain transactions have exact transaction UUID/digest idempotency: the same transaction returns the same Core retention UUID/revision ACK, including historical retry. Changed reuse conflicts. Sixty-four bounded receipts remain on the same original row. Uncertain is its own non-drained transactional ACK; it cannot be replaced by a quarantine flag. Dispatch claim, result fingerprint, quarantine and physical retirement use private bookkeeping revisions without advancing the producer's CPU ordinal. Running ACK requires fresh selected scope/Core checks before FFI. A result fingerprint is `{status, contentType, sha256, bytes<=1440044}`, retained after CPU terminal and before body delivery; it is immutable once set.

One `voice-cpu-supervisor` original binds the exact scope before spawn. Its control has profileDigest, Node owner/boot/generation/lease, actual worker boot bound once, original recovery endpoint identity and retirementSecretSha256. The secret stays in the helper. A fixed instance may have one unretired control, and owner generations strictly increase. Private list returns the newest 128 controls for that fixed instance. Replacement requires positive original physical retirement, not a missing process or lease deadline. Resource retirement retains a bounded content-free verified receipt on the same row. After producer loss it may prove the original tree is gone while leaving the public outcome unknown and the last CPU producer state uncertain; no completed inference is invented.

`retireOriginal` on a supervisor control also seals every unretired CPU original with that exact controlOperationId and full immutable Node owner tuple, including Node boot/generation/lease. One indexed query admits at most 1024 leaves; 1025 refuses without callbacks or mutation. Core checks each leaf's exact scope and bound worker boot. The SAME opaque physical scope proof is passed to verifyRetirement for the control and each leaf; the callback must verify that tuple without consuming the proof or performing new physical work. All positive receipts are validated before writes. Parent and leaves then commit in the SAME Core transaction, or every bookkeeping change rolls back. Public outcomes, result fingerprints and CPU producer revisions stay unchanged. A parent-only receipt from the earlier implementation does not skip pending leaves: fresh positive validation of the retained original proof is required to reconcile them. Foreign controls/owner tuples are excluded; contradictory same-owner scope metadata fails closed.

Root owns the actual selected-conversation and positive-retirement callbacks, SQL128 registration/application, original VoiceService adapter and all runtime/auth acceptance. Existing VoiceService reserve calls do not supply an original UUID, input fingerprint or owner lease; a concrete server adapter must derive those from the actual request/payload/original owner before dispatch. Missing fields are refused, never generated from guessed session/task/native IDs. CPUv2 workers consume the same read/CAS ledger instance through their private original owner.

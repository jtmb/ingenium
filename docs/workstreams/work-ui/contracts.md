# Work UI local adapter contracts

Consumes coordinator `docs/contracts/veyra-parallel-v1.md` semantics (read 2026-10-29). These shapes are local component proposals and do not supersede the coordinator's versioned DTOs or existing runtime/API authority.

`WorkIdentity` scopes in-memory drafts by installation surface, user, organization, nullable project, runtime, workspace and nullable engine session. It encodes the tuple with JSON, avoiding concatenation collisions. The current compatibility route uses existing ProjectContext/runtime names; it does not synthesize a projectless/global project mapping. The Projects adapter must supply the explicit null project under the new contract.

`WorkDraft` carries text, file reference/data URLs, explicit skill IDs, provider/model/variant. Draft state does not grant attachment/tool/skill authority. The current runtime consumer sends only supported text/file parts and model/variant; skill activation awaits the resource lifecycle adapter. Unknown admissions retain the exact draft and a visible unconfirmed status. Reload durability and exact admission receipts remain owned integration contracts.

`WorkProject {id,label,conversations}` and `WorkConversation {id,title,pinned?,busy?}` are presentation projections from an already permission-filtered catalog. WorkShell does not create/rename/archive projects or modify pin preferences. `onSelect(id)` must resolve the existing engine session on its admitted execution binding, never match titles or move a conversation implicitly.

`WorkModel {providerId,modelId,label,variants?}` contains only qualified catalog choices. The composer clears the old variant on explicit model change. Existing session provider/model/variant comes from native session metadata; new-session defaults come from the API-owned installation preferences adapter. Missing native selection/catalog blocks send and asks for explicit selection; Work does not write settings or silently copy last-chat choices into defaults.

`WorkRuntime` now accepts minimal parent props: `webQualification {protocol,runtimeId,workspaceId}` (default null, no launch), `admissionControl: ReactNode` for the existing controller's read/recovery UI, and `submissionBlockedReason: string|null` for its current admission fence. A foreign runtime/workspace qualification is rejected. These presentation props do not mint capabilities, clear unknown originals, write receipts or grant native execution. The coordinator supplies them from actual execution/capability state, not folder labels or a Docker source pin.

Native reuse inspected read-only: `windows-source/apps/web/src/features/tasks/submission/useTaskSubmission.ts` already owns exact originals, service-instance/project-revision/model binding, retained-admission reads and explicit reconciliation; `features/workbench/useComposerDraft.ts` owns scoped native draft handling. The native admission hook currently qualifies exact Windows model/context and rejects unsupported WSL admission. Do not copy this authority into dashboard storage, import the Windows inference engine into Linux, or map provider/model strings to native quant/context by guesswork. The coordinator must mount/adapt these controllers above Work/composer lifetimes and replace compatibility transport through a reviewed port before claiming durable admission parity. Current compatibility `sessions.create`/`chat.send` provide no exact receipt ID on unknown outcomes, so Work keeps a local blocking witness and cannot safely clear it by checking titles or matching prompt text. That gap remains open; the UI guard is not a new durable journal.

`WorkShell` provides named `composer`, `web`, `status`, `tools` and `dot` React slots. `WorkComposer` provides `projectControl`, `environmentControl`, `permissionControl`, `memoryControl`, `voiceControl` slots and attachment callback. Domain controllers remain in the owning streams. Pass real capability/status/error controls; sidebar placement does not grant admission. These slots avoid direct dependencies on still evolving resource, scheduling and voice implementations.

`WorkRuntime` now forwards those domain slots through an exact five-field `WorkContextSlots.binding` presentation fence, plus a standalone `projectPicker` available when the runtime is unbound/offline. See [controller wiring and lifetime requirements](context-bindings.md). Unmatched controls are removed rather than silently rebound to the current conversation. This does not replace the domain controller's authority checks or add a new persistence owner.

Required addition from coordinator: an `ExecutionBinding`/`ConversationRef` adapter carrying instance/revision/immutable workspace hash/epoch, actual native/WSL/cluster host/directory and project organization independently. Work's source-verified2.0.11 Web route now derives only its HTTP server presentation key from the authorized public gateway origin; it never derives an execution binding from it. Confirm the served upstream version and same admitted runtime through the existing health/launch contract, plus exact operation receipts and cross-view recovery, before automatic toggle acceptance. Do not derive execution fields from folder labels or iframe DOM.

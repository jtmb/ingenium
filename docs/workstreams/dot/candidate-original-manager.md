# veyra-bot original manager waiting/readiness source proposal

This nine-target patch implements a genuine bounded Docker I/O owner in source. It is not another positive-proof callback wrapper. The module has no Docker/Core/clock/signer/spec/factory injection ports. It imports node:http directly, opens only /var/run/docker.sock at /v1.45, loads only the existing protected runtime-manager token file, and calls a separate fixed private Core candidate prefix. Import is inert. No actual Docker, auth, credentials, native child, build or image cases were run.

The original immutable Core admission must already exist. GET /api/v1/internal/original-candidate-job-runs/:run/admission returns exact intent/intentHash/specHash/selectionSha256/phase/revision (prepared/0), never a new Run, attempt, selection or deadline. Root owns these currently missing authenticated endpoints. A missing endpoint refuses before Docker. The owner validates the actual pure candidate intent, original deadline and current protected selection file, canonical workspace mapping hash/resources, immutable image ID and exact parent profile/start/scope. Each effect gets a fresh Core current-context check against the same persisted admission and source.

Process restart loses opaque handles and must remain closed; JSON cannot restore them.

The credential-free waiting spec uses the original validated mapping read-only, original scoped limits, network none, no exposed ports, no privileged/PID-host/device/capability additions, read-only root, fixed tmpfs, fixed image/entrypoint and candidate role.

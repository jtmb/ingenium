# Core-owned Linux CPU producer

The Linux API directly supervises the existing CPU speech worker. It does not
construct the Windows Rust service or inference engine. `managed-supervisor.mjs`
retains the actual original helper Child, private-channel pumps, bootstrap writer,
original tree proof and recovery witness Child. Construction and status launch
nothing. `CoreCpuOwner` uses the installed SQL128 Core owner for every operation,
dispatch claim, CPU CAS acknowledgement and result fingerprint. There is no
second SQLite connection, file journal or renderer-supplied authority.

Root integration must construct the real `createVoiceOperationOwner` with its
actual selected-conversation/auth/runtime `currentScope` callback. Its
`requireOriginalResource` and `verifyRetirement` callbacks delegate to the retained
manager, after Root's context binding verifies this exact manager-owned resource.
Construct the ledger with closures referencing a subsequently assigned manager;
neither constructor calls the closures or starts work. Supply real `bindContext`,
`admitCpu`, `requireCpuAdmission` and `releaseCpu`; none has an allow default.
The admission carries the actual absolute deadline and accounts for the model
set, CPU threads, original helper and metadata-only witness peak. Root must keep
the Core writer available until shutdown/recovery bookkeeping commits.

The protected profile hashes the interpreter and the closed eleven-file worker
bundle, approves only CPU/offline settings and chooses an explicit abstract Unix
recovery transport. It is backend configuration, never an HTTP request. Root owns
Python 3.12, locked packages/native libraries, assets, dedicated token, approved
scratch and the actual installed-container profile. No installs are performed by
this source. Each hot scope loads its prepared model set once; child HTTP requests
reuse it. A distinct active conversation cannot replace a live scope. Last-session
release closes admission and requests physical shutdown.

The fixed Linux helper uses a qualified subreaper/pidfd design, not host cgroup
delegation. Before CPU execution, it retains original child custody and opens the
authenticated private channel. Core binds the actual Python worker boot separately
from Node boot. Shutdown requires ECHILD, original leader wait, descendant pipe EOF,
the actual helper kernel exit and completion of the Node-held originals. A fixed
model-free witness captures the connected original helper peer pidfd before its
exit ACK. The helper-only retirement capability is removed from the CPU child's
environment. Only its hash enters Core. Recovery validates the original Core
owner/control/hash and actual old parent exit; a live old owner is not adopted.

Core's control retirement validates the same opaque physical proof for the
control and every exact unretired CPU leaf in one transaction. The callback is
read-only: joins and proof capture precede SQL, and existing terminal leaves retain
their actual Core-issued CPU retention IDs. The public unknown result and private
CPU producer revision are never rewritten by physical cleanup. CPU result bytes
must match the private retained fingerprint before delivery; result/usage/HTTP ACKs
are not physical retirement proof. Dispatch handles are non-reusable and carry no
renderer authority. Closing consumes unpublished payload gates before shutdown.

If the entire original container/helper disappears before its proof is committed,
endpoint absence, PID absence, health and elapsed time remain insufficient. Keep
the original unknown until Root's actual original container manager can prove
retirement. This source does not invent that missing manager capability.

Validation for this checkpoint: 58 dependency-free Python unit cases passed on
the existing Python 3.14 runner (prepare fixtures explicitly fake 3.12/model
loading). The 57 selected API cases and 20 package CPU/continuous cases passed
on Node, including eight private-channel/Core-port fixtures. All process/socket/
kernel operations in these new tests are fake or absent. The fixture runner
removed its exact synthetic root and 3,614 Linux bytes, with no retained exception.
There was no build, install, actual helper launch, inference, audio/device use,
container change, Windows Native compilation or runtime qualification.

The Windows Native proposal in this directory is a separate unapplied draft;
its old generated patch is not this Linux checkpoint and requires regeneration
and Root review before use. The next worker change is the concrete VoiceService,
current-agent and CPU speech consumer over these actual Core operations. Actual
API conversation/auth/runtime registration, resource admission, inert-helper
qualification, real speech and full Phase 1/release acceptance remain with Root.

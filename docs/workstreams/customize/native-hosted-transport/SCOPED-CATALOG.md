New closed browser-session/CSRF routes alongside the existing project catalog:

- GET `/api/v1/customize/project-source?projectId=<actual UUID>&kind=plugin|skill&name=<name>` provides the original reviewed source/hash/revision.
- GET `/api/v1/customize/sources?visibility=personal|public|system&after=<cursor>&limit=1..100` and `/sources/:id` discover/read authorized published content.
- POST `/api/v1/customize/commands` accepts `CatalogCommandSchema`: `publish`, `withdraw`, `restore-source`, `revise-plugin-source`, `connect`, `archive-plugin`, `restore-plugin`, `activate-plugin`, `deactivate-plugin`, `reconcile-plugin-projection`. The reconciliation command accepts only the source original selector and actual server review hash; GET `/projection-reconciliation/:operationId` derives that review from the original private witness and actual filesystem. Each requires a fresh canonical `operationId`; write review fields come from the actual original GET. No actor, cookie, credential, endpoint or success/proof fields are accepted.
- GET `/commands/:operationId` checks current actor/installation/organization/project authority and returns the immutable first receipt or explicit unknown. GET `/archived-plugins?projectId=...` and `/installations?projectId=...` return actual existing records.

Commands and source contracts are in the new Core module, with original authentication rechecked in `customize-scoped.ts`. Outer authorization admits only an actual browser session; the Core owner independently checks actual active user, organization, target project, installation, source and execute/admin permissions. Receipts never supply authority. Metadata is separate from workspace resource ownership and existing encrypted credentials. New command IDs, source IDs and installation provenance are genuine Core-writer records; no synthetic authorization rows are inserted.

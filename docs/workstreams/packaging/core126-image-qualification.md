# Core126 original-manager image qualification bridge

This source-only proposal supplies a deterministic manifest producer, an immutable-image approval registry, an original-manager full-observation producer and a typed request-scoped `imageOwner` for the actual Core126 factory. It does not qualify the current image, dispatch a model, create a container, grant a capability, replace a manager token or change original Core persistence. Root owns the original server wiring, Dockerfile/build, actual inert-image harness, reviewed approval and platform acceptance.

## Manifest and independent approval

`tools/veyra-release/core126-image-qualification.mjs` exports `produceCore126ImageManifest`. Its `.d.mts` declares the actual source, image-reader and inert-harness ports Root must supply. It has no default ports, process/Docker launch, network transport, arbitrary tag selection or expected-result generator. Production ports must read the actual original frozen Source and immutable image; they must never echo `PROTOCOL_CASES`. The tests intentionally use synthetic CPU fixtures and grant no image authority.

The producer binds the exact original Git revision and full Source SHA256 to required critical source byte hashes; raw OCI config bytes must hash to the actual `sha256:<config digest>` Docker image ID. It requires Linux/amd64, `user-runtime`, the existing appuser image configuration, fixed runtime entrypoint and no default command. Absent OCI Cmd is normalized to null. The independently approved image must equal the actual original parent image ID, with no tag or other-image fallback. Config labels are consistency checks against independently selected frozen Source, never authority.

It measures exact image paths for the runtime entrypoint, child wrapper, model-bound child, original HTTP handler, CLOSED job broker, emitted runtime closure, OpenCode binary, managed configuration, job-only configuration, agent-material implementation, immutable reserved broker profile and both protected broker/job-agent enforcement plugins. Every artifact must be a root-owned regular file, with no group/world write. For the copied child/HTTP modules, actual closure source/path/emitted hashes must agree with both the frozen source and measured image bytes. Root's image reader must reject archive traversal, symlinks/hardlinks and unstable reads, report real UID/GID/mode, and read files by the selected immutable image ID. Do not synthesize metadata or follow a mutable tag.

The exact thirteen inert cases in `core126-image-contract.mjs` cover actual fixed child argv including `--model`, job-run audience/scoped broker route with zero generic preflight, wrong-audience denial, wrong-run/attempt denial, private-tool denial, changed-grant denial, unqualified-assignment denial and original attempt-bound result submission. Five additional cases require exact Core canary agent/ordered-permission hash in the native merged registry, changed-agent and changed-permission denials before child/model dispatch, a closed job-only config with zero generic bootstrap, and actual protected reserved-broker tool denial. Root's reviewed harness must run these against the selected actual image files and original Core handler owners with inert canaries. Stub model dispatch/spawn at the documented injection boundary: do not load a model merely to qualify packaging. Bind the reviewed harness implementation SHA256 and image/artifact-set hashes into every actual case. The manifest retains only hashes, status and fixed case identity; preserve minimal actual harness receipts externally in the existing task root. This is image/protocol qualification evidence; final live model, workflow, security, resource, persistence and platform gates remain separate.

Canonical manifest JSON contains no timestamp, so identical measured inputs produce identical bytes. The producer returns `approvalGranted:false`. Root independently reviews and supplies the registry policy `{imageId,manifestSha256,sourceRevision,sourceSha256,validUntil}`. `createCore126ImageRegistry` checks the raw manifest digest, source identity and schema, and caches its sealed immutable definition once per approved image ID. Failure stays failure. A manifest boolean, Docker label, supplied file, alternate image or caller-defined cache entry cannot approve itself.

A deterministic manifest is not a bit-reproducible Docker build. The observed Dockerfile still contains mutable base/apt inputs; the separately delivered reproducibility recipe remains a separate gate until Root integrates and verifies it. Root must bind the actual image build/material receipt to the frozen Source and independently inspect the image. Raw OCI config can be read from Root's existing OCI/BuildKit content owner by its config digest; do not reconstruct OCI bytes from `docker inspect` JSON. Reuse the existing image/content storage, stream required file reads through an inert qualification container/archive reader, and retire reproducible extraction/build outputs after their consumer. No extra full image archive or source/dependency snapshot is required by this proposal.

## Core wiring and no-await transaction boundary

Construct `createCore126ImageOwner({client,registry,originalProvisionProfile,inTransaction:()=>getDb().inTransaction})` once in the original server composition owner. It matches the current actual factory's `qualifyOriginalJobRole` and synchronous `assertCurrentOriginalJobRole`. Missing original ports refuse; no bool/label fallback exists. The original factory keeps provider resolution, exact provider binding hash, agent deployment validation, original parent capability scopes, tool visibility/grants and existing resource admission authority.

Root must expose/reuse original Core's current-facts read, then wrap EVERY qualifying/lifecycle/credential/broker path needing launch authority as follows, outside any transaction:

```ts
const facts = originalCoreCurrentFacts(selection, originalContext);
return imageOwner.withFreshOriginalJobRole(facts, () => originalOperation());
```

The original operation must reread original authorization, run/job/runtime/workspace/agent/provider state inside its existing synchronous transaction and call `profiles.assertCurrent(admission, currentFacts)` there. In particular the observed Core126 `prepare` awaits `profiles.qualify`, then enters its FIRST insert transaction without that image assertion; add it before insertion too. Keep existing CAS/effect fences and original credential issuance/result/broker validation. Never await Docker, provider lookup or network inside Core's transaction, and never relax the no-await boundary. If provider/catalog work consumes the observation TTL, refuse; obtain a new request observation only outside the transaction through the original owner, with original effect/retry rules preserved.

Each request owns its sealed observation through AsyncLocalStorage. A second request cannot use another run's scope. The synchronous assertion refuses scope, epoch, revision, resource, agent, model binding, image/profile, deadline or approval changes. It makes zero network calls and never refreshes. The lease closes in finally when its request finishes, including on errors; detached continuations cannot retain authority. Observation freshness is five seconds; the stable admitted profile hash excludes timestamps, and its expiry is min(independent approval validity, original runtime absolute expiry), so this proposal does not truncate jobs to five seconds. Core retains its original job timeout/runtime/deadline checks.

The manager must call `assertAdmissionOriginalImage(admission, itsOwnFreshProbe, sealedApprovedDefinition, registry)` immediately before EACH create AND start using its own original Docker producer, then preserve the original Core claimEffect/CAS fence and unknown-result handling. The helper binds the full admitted scope/limits/model/agent/profile/deadline to the freshly reobserved original daemon/parent/image. Do not reuse a pre-create probe for start, manufacture an image definition from caller JSON, retry an unknown create/start, or dispatch a replacement model on refusal. Full current Core checks remain necessary alongside the manager's local proof. The helper intentionally performs no effect and supplies no new authority.

The current runtime copy script already includes `packages/veyra-operations` and rewrites static `.mjs` imports into the API's `dist/veyra-packages` closure. Root should add a tiny original `dot-v2` facade importing these package modules, with matching declaration, and have compiled TS import that facade. Do not rely on an uncopied raw package path or silently add a build output location. These files use Node builtins only and require no new dependency/lock changes.
